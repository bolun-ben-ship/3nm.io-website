Before you write the job description

Most founders solve this by hiring.
Most founders solve it wrong.

By the time you're writing the job description, the work has shaped itself around you. The operating manual lives in your head. The data lives in five tools. Half the team's processes were never written down.

Whoever you hire spends six months reverse-engineering the business. You pay their salary while they do it. You stay the bottleneck while they do it.

Build the system first. Either the hire walks into a working machine and runs it from day one, or the work turns out to be systemisable enough that the next hire is smaller, cheaper, more focused. Either way, the next hire is one you make from clarity.

What counts as a Function
  • Connecting a new data source or external system
  • Automating a workflow that needs a human decision today
  • Surfacing information that requires manual compilation today
  • Building a new interface or module that didn't exist
  • Creating a new AI workflow, agent, or automation
e.g. new Xero integration, automated report pipeline, BI dashboard from a new data source, new AI agent.
What counts as an Enhancement
  • Search and filtering on an existing view
  • CSV or PDF export of existing data
  • Notes, comments, or tags on any record
  • Notifications triggered by existing logic
  • Sorting, pagination, date filters
  • UI tweaks to existing views
  • Adding columns to an existing table
