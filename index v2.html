Before you write the job description

Most founders solve this by hiring.
Most founders solve it wrong.

By the time you're writing the job description, the work has shaped itself around you. The operating manual lives in your head. The data lives in five tools. Half the team's working processes were never written down.

Whoever you hire will spend their first six months reverse-engineering the business. You'll be paying their salary while they do it. You'll still be the bottleneck while they do it.

Build the systems first and one of two things happens. Either the hire walks into a working machine, plugs in, and runs it from day one. Or the work turns out to be systemisable enough that you don't need the hire — or you need a smaller, cheaper, more focused one.

Either way, the next hire is one you make from clarity. Not from desperation.

The hire isn't the problem.
The hire walking into chaos is.

What counts as a Function
  • Connecting to a new data source or external system
  • Automating a workflow that currently requires a human decision or manual step
  • Surfacing information that currently requires someone to compile manually
  • Building a new interface or module that did not previously exist
  • Creating a new AI workflow, agent, or automation
Examples: new Xero integration, automated report pipeline, student portal, review board, BI dashboard from a new data source, new AI agent.
What counts as an Enhancement
  • Search and filtering on an existing view
  • Export to CSV or PDF of existing data
  • Notes, comments, or tags on any record
  • Notifications triggered by existing logic
  • Sorting, pagination, date range filters
  • UI or visual changes to existing views
  • Adding columns or fields to an existing table
Enhancements are included during active builds. In Maintain Mode: 2 free per quarter, then SGD 300 each. If it is not on this list, it is a Function.
